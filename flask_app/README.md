# Crypto Sentinel — separate Flask framework

This directory is a parallel Flask application. It does not replace or modify the existing Streamlit app at the repository root or the GitHub Pages website.

## Run locally (Python 3.10+)

```powershell
cd flask_app
python -m venv .venv
.venv\\Scripts\\Activate.ps1
pip install -r requirements.txt
$env:FLASK_SECRET_KEY='use-a-long-random-secret'
python app.py
```
Open http://127.0.0.1:5000.

## Workflow
1. Upload a video to create an evidence session with frame SHA-256 hashes, sequential chain links, timestamps and heuristic scene indicators.
2. Download and protect the original reference JSON independently.
3. Upload the same video and trusted reference JSON to verify frame and chain integrity.
4. Register a demo Ed25519 camera identity and use the challenge endpoints to demonstrate registered-key possession.
5. Run record-level modification, deletion, insertion, reordering, replay and timestamp attack simulations.
6. Download a JSON session report.

## Important limitations
- SHA-256 only proves consistency against a trusted reference; it does not prove source or scene authenticity.
- The camera keypair is generated by the server for demonstration. The current video upload pipeline does not verify signatures produced by trusted camera hardware. No TPM/secure-element attestation is implemented.
- A software nonce proves key possession only when signed; it does not prove a physical scene is live. A separately controlled visual indicator or authenticated sensor is required.
- Masking, blur and frozen-frame checks are heuristics and can have false positives/negatives. Static scenes may be legitimate.
- Sensor hardware integration, trusted timestamp authority, production key custody, full physical challenge-response, YOLO model integration and complete hardware-backed source authentication remain future integrations.
- The attack lab mutates reference records to demonstrate hash-chain detection; it is not a physical camera or live stream injection test.
- Configure FLASK_SECRET_KEY and persistent storage before deployment. The default secret is for local development only.

## Separate hosting
Create a new web service using this directory. Build command: pip install -r flask_app/requirements.txt; start command: gunicorn --chdir flask_app app:app. Set FLASK_SECRET_KEY and a persistent disk/data directory. Do not change the existing Streamlit service settings.
